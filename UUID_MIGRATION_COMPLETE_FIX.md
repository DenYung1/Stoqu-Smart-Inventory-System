# UUID Migration Fix - Complete Solution with Relationship Preservation

## Problem
Users were encountering `invalid input syntax for type uuid` errors (PostgreSQL error code 22P02) and foreign key constraint violations (PostgreSQL error code 23503) when syncing data to Supabase. 

Example errors:
```
{code: '22P02', details: null, hint: null, message: 'invalid input syntax for type uuid: "v93ibkf4h"'}
{code: '23503', details: 'Key is not present in table "products".', message: 'insert or update on table "stock_movements" violates foreign key constraint "stock_movements_product_id_fkey"'}
```

## Root Cause
1. **Legacy ID Format**: The app originally used short alphanumeric IDs (like "v93ibkf4h") generated by a simple string generator
2. **Database Schema Change**: Database was updated to use UUID columns with foreign key constraints
3. **Broken Relationships**: Initial migration converted IDs independently, breaking foreign key relationships between entities

## Migration Process

### Automatic Migration
1. **On App Load**: When user data is loaded from localStorage, the migration function runs automatically
2. **Relationship Analysis**: First pass collects all IDs across all entity types
3. **UUID Generation**: Creates consistent UUID mappings for all invalid IDs
4. **Relationship Preservation**: Second pass applies the same UUID mappings to maintain foreign key integrity
5. **Persistence**: Saves migrated data back to localStorage
6. **Sync**: Migrated data with proper UUIDs and preserved relationships syncs successfully to Supabase

### What Gets Migrated

#### **Entity IDs**
- Products: `id` → UUID
- Sales: `id` → UUID  
- Suppliers: `id` → UUID
- Stock Movements: `id` → UUID
- Notifications: `id` → UUID

#### **Foreign Key Relationships** 
- Sales → Products: `productId` maintains correct reference
- Stock Movements → Products: `productId` maintains correct reference  
- Products → Suppliers: `supplierId` maintains correct reference
